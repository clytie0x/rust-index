11.1 ทำไมต้องมี lifetime

ฟังก์ชันเลือกข้อความที่ยาวกว่า ทางที่ไม่มีเรื่อง lifetime คือสำเนาเป็น String แล้วคืนของที่ฟังก์ชันเป็นเจ้าของ ผู้เรียกได้ก้อนใหม่ ไม่ผูกกับอาร์กิวเมนต์

คืนของตัวเอง

fn longer_owned(a: &str, b: &str) -> String {
    if a.len() >= b.len() {
        a.to_string()
    } else {
        b.to_string()
    }
}

fn main() {
    let text = longer_owned("Ann", "Mali");
    println!("{text}");
}
Mali

len นับไบต์ แบบที่หน้า 1.3 เตือนไว้ Mali ยาวกว่า Ann จึงถูกสำเนาออกมา การสำเนาปลอดภัย แต่เปลืองเมื่อข้อความยาวและเราแค่จะชี้ของเดิม

ลองทำให้พัง

ถ้าคืน &str เพื่อไม่สำเนา rustc ต้องรู้ว่าผลชี้ไปที่ a หรือ b ลายเซ็นด้านล่างไม่บอก จึงไม่ผ่าน

fn longer(a: &str, b: &str) -> &str {
    if a.len() >= b.len() { a } else { b }
}

fn main() {
    println!("{}", longer("Ann", "Mali"));
}

สรุป

  • คืน String ได้โดยไม่ต้องพูดถึง lifetime เพราะผู้เรียกได้ของใหม่
  • คืน &str คือการชี้ของเดิม rustc ต้องรู้ว่าของใคร
  • มีตัวยืมเข้าสองตัวแล้วไม่บอกป้าย rustc จะถามเอง
