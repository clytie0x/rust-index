0.3 อ่าน error จาก rustc

เขียนโปรแกรมแล้วเจอ error เป็นเรื่องปกติ คนที่อ่าน error ออกจะเดินต่อได้เร็วกว่าคนที่ทิ้งแล้วเริ่มใหม่ หน้านี้ทำให้พังทีละแบบ แล้วกลับมาแก้ให้ถูกก่อนลองแบบถัดไป

ข้อความด้านล่างคัดจาก rustc --edition 2021 จริง ตัดบรรทัด aborting due to ... ท้ายข้อความออก เพราะซ้ำกับ error ด้านบน

ลืม ;

เปิด src/main.rs แล้วลบ ; ท้ายบรรทัด println! บรรทัดแรก จากนั้นใส่ println! อีกบรรทัดให้มีคำสั่งถัดไปให้คอมไพเลอร์ชี้

fn main() {
    println!("Hello, world!")
    println!("next");
}

รัน cargo run จะไม่เกิดโปรแกรม แต่ได้ข้อความประมาณนี้

error: expected `;`, found `println`
 --> main.rs:2:30
  |
2 |     println!("Hello, world!")
  |                              ^ help: add `;` here
3 |     println!("next");
  |     ------- unexpected token

อ่านแบบนี้

  • บรรทัด error บอกว่าขาด ;
  • main.rs:2:30 คือไฟล์ main.rs บรรทัด 2 ตัวอักษรที่ 30
  • เครื่องหมาย ^ ชี้จุดที่ควรใส่ ; และ rustc เขียนวิธีแก้มาให้ในบรรทัด help

ใส่ ; กลับไปแล้วรันใหม่ ต้องผ่าน

พิมพ์ชื่อมาโครผิด

fn main() {
    println!("Hello, world!");
    prinltn!("next");
}

error: cannot find macro `prinltn` in this scope
 --> main.rs:3:5
  |
3 |     prinltn!("next");
  |     ^^^^^^^ help: a macro with a similar name exists: `println`

rustc ยังพิมพ์โน้ตที่ชี้เข้าไปในไลบรารีมาตรฐานต่อจากบรรทัดนี้ ยาวและยังไม่ต้องอ่าน ดูบรรทัด help พอ มันเดาได้ว่าเราหมายถึง println

อ่านบรรทัด error แรกก่อน

ข้อความที่ตามมาบ่อยครั้งเป็นผลพวงจากจุดแรก แก้จุดที่ ^ ชี้ แล้วรันใหม่ อย่าพยายามแก้ทุกบรรทัดพร้อมกัน

สรุป

  • cargo run ที่ไม่ผ่านจะโชว์ข้อความจาก rustc
  • เลขหลังชื่อไฟล์คือบรรทัดกับตำแหน่งตัวอักษร
  • บรรทัด help มักบอกวิธีแก้ตรงตัว อ่านก่อนลงมือเดา

พอแก้ error ทั้งสองแบบได้แล้ว กลับไปติ๊ก ผ่านบทนี้เมื่อ ให้ครบ แล้วไปแบบฝึกหัด
