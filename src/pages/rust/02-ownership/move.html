2.1 move กับ Copy

พอมีตัวแปรมากกว่าหนึ่งชื่อ คำถามแรกคือค่าถูกก๊อปปี้ หรือถูกย้ายไปอยู่กับชื่อใหม่ Rust ตอบไม่เหมือนกันทุกชนิด

จำนวนเต็มถูกก๊อปปี้

fn main() {
    let a = 10;
    let b = a;
    println!("{a} {b}");
}

10 10

i32 เล็กและก๊อปปี้ได้ครบด้วยการก็อปบิต หลัง let b = a ทั้งสองชื่อยังใช้ได้ ชนิดแบบนี้เรียกว่ามีพฤติกรรม Copy

String ถูกย้าย

String ถือก้อนข้อความในหน่วยความจำที่โตได้ ถ้าก๊อปปี้ทั้งก้อนทุกครั้งที่ส่งต่อ จะช้าและงงว่าก้อนไหนเป็นของจริง Rust เลยย้าย (move) ความเป็นเจ้าของไปชื่อใหม่ ชื่อเก่าใช้ไม่ได้

fn main() {
    let name = String::from("Ann");
    let other = name;
    println!("{other}");
}

Ann

หลังบรรทัด let other = name เจ้าของคือ other โปรแกรมนี้จึงพิมพ์ผ่านชื่อใหม่ชื่อเดียว

ลองใช้ชื่อเดิมหลังย้าย

fn main() {
    let name = String::from("Ann");
    let other = name;
    println!("{name}");
    println!("{other}");
}

error[E0382]: borrow of moved value: `name`
 --> main.rs:4:15
  |
2 |     let name = String::from("Ann");
  |         ---- move occurs because `name` has type `String`, which does not implement the `Copy` trait
3 |     let other = name;
  |                 ---- value moved here
4 |     println!("{name}");
  |               ^^^^^^ value borrowed here after move

อ่านสามจุดบนลูกศรในกล่องนี้ก็พอ ค่าถูกย้ายที่บรรทัด 3 และถูกใช้ต่อที่บรรทัด 4 ชนิด String ไม่ได้ถูกก๊อปปี้เอง

rustc ยังเสนอให้เรียก clone เพื่อก๊อปปี้ข้อความทั้งก้อน ชุดนี้ยังไม่ใช้ทางนั้น ถ้าต้องการทั้งสองชื่อให้อ่านแบบยืมในหน้าถัดไป จะไม่ต้องก๊อปปี้

คำว่า trait ในข้อความ error

trait คือชุดความสามารถที่ชนิดหนึ่งมี ตอนนี้จำแค่ประโยคนี้ String ไม่มี Copy จึงถูกย้าย ไม่ถูกก๊อปปี้

สรุป

  • i32 และชนิดเล็กๆ อีกหลายตัวถูกก๊อปปี้ตอนกำหนดค่าให้ชื่อใหม่
  • String ถูกย้าย ชื่อเก่ายืมต่อไม่ได้
  • error รหัส E0382 คือใช้ค่าหลังถูกย้าย
